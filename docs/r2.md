# Listening audio on Cloudflare R2 (M5-B1)

Listening recordings live in an R2 bucket per environment and are streamed from the bucket's
public domain. The admin builder (M5-A1) uploads them straight from the browser to R2, using a
short-lived presigned URL from the `r2-upload-url` Edge Function, so the R2 keys never reach a
browser.

```
admin builder ──POST r2-upload-url──▶ Edge Function (staff only, signs a 15-min PUT URL)
      │                                      │ R2 secrets (Supabase secrets)
      └──PUT file (progress) ─────────────▶ R2 bucket ──▶ https://audio…prepora.site/<key> ──▶ player
```

Map and diagram images (M5-B3) are in Supabase Storage instead: the public `listening-images`
bucket, created by migration `20261125200000_listening_backend.sql` (staff upload; PNG, JPEG or
WebP up to 5 MB). Nothing to set up for those.

## One-time setup (per environment: staging, then production)

Done by an account owner; nothing here is automated, and no key goes in the repo.

1. **Create the bucket** (the apps use Wrangler, so use it here too):

   ```sh
   npx wrangler r2 bucket create prepora-audio-staging      # production: prepora-audio
   ```

2. **Public domain.** In the Cloudflare dashboard → R2 → the bucket → Settings → Custom Domains,
   connect `audio-staging.prepora.site` (production: `audio.prepora.site`). That's what students
   stream from, so it gets Cloudflare's cache. Don't use the `r2.dev` URL for production: it's
   rate-limited.

3. **CORS**, so the admin's browser may PUT to the bucket. Dashboard → R2 → the bucket →
   Settings → CORS policy:

   ```json
   [
     {
       "AllowedOrigins": ["https://admin-staging.prepora.site", "http://localhost:3001"],
       "AllowedMethods": ["PUT", "GET", "HEAD"],
       "AllowedHeaders": ["content-type"],
       "ExposeHeaders": ["ETag"],
       "MaxAgeSeconds": 3600
     }
   ]
   ```

   Production: `https://admin.prepora.site` only (no localhost).

4. **API token.** Dashboard → R2 → Manage R2 API Tokens → Create API token: **Object Read &
   Write**, limited to this one bucket. Copy the Access Key ID and Secret Access Key (shown once).
   The Account ID is on the R2 overview page.

5. **Supabase secrets** for the Edge Function (run it yourself; never commit the values):

   ```sh
   supabase secrets set --project-ref <staging-ref> \
     R2_ACCOUNT_ID=<account id> \
     R2_ACCESS_KEY_ID=<access key id> \
     R2_SECRET_ACCESS_KEY=<secret access key> \
     R2_BUCKET=prepora-audio-staging \
     R2_PUBLIC_URL=https://audio-staging.prepora.site
   ```

   Until these are set, `r2-upload-url` answers **503 "Audio uploads aren't set up yet"**.

## Local development

`supabase functions serve` reads `supabase/functions/.env` (gitignored). To upload for real,
put a **dev** bucket's values there (its own token, never production's). To run the e2e tests
without R2, any placeholder values work: the function only signs URLs, it never calls R2 (CI
does exactly this, see `.github/workflows/e2e.yml`).

## How the upload URL works

- `POST /functions/v1/r2-upload-url` `{ test_id, section, content_type, size_bytes }`
  → `{ upload_url, method: "PUT", headers: { "Content-Type" }, key, public_url, expires_in }`.
  Contract: `packages/shared/src/api/r2-upload.ts`.
- Staff only (admins and content editors, who both build tests); the test must exist.
- Types: MP3, M4A/MP4, WAV, OGG, WebM; up to 100 MB (a section is 6–10 minutes).
- The URL is an S3 SigV4 presigned PUT (region `auto`), valid 15 minutes, for one key and one
  Content-Type (signed: another type is refused by R2). Signed in `_shared/r2.ts` with WebCrypto,
  checked against AWS's published example (`tests/r2.test.ts`).
- Keys: `listening/<test id>/section-<n>-<random>.<ext>`: a re-upload never overwrites
  what students may be streaming; the builder saves the new `public_url` as the section's
  `audio_url`.
- Not enforced by the URL: the size (it's checked when the URL is asked for; R2 itself caps a
  single PUT at 5 GB). Old recordings replaced by a re-upload stay in the bucket; cleaning them up
  can come with the builder.
